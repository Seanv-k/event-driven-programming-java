# Procedural vs Event-Driven Programming

| Feature | Procedural Calculator | Event-Driven Calculator |
|---|---|---|
| Program flow | Executes instructions in order. | Responds to user actions (events). |
| User interaction | Uses terminal input through Scanner. | Uses buttons and a graphical interface. |
| Control | The program controls the sequence. | Events determine when handlers execute. |
| Main components | Scanner, variables, switch statement. | JFrame, JButton, JTextField, ActionListener. |
| Execution | Waits for input in a fixed sequence. | Waits for events such as button clicks. |
| Best suited for | Simple calculations and sequential tasks. | Interactive applications and graphical programs. |

## Reflection

The procedural calculator follows a fixed sequence of instructions. It asks the user to enter numbers and an operator before calculating the result. The event-driven calculator uses a graphical interface and responds to button clicks. Event-driven programming is useful when developing interactive applications because users can control when actions happen. I found that event-driven programming requires event listeners and handlers to respond to user actions.
